## P0：收费功能的额外门槛

当前线上环境明确为 `CHECKOUT_MODE=offline`，所以不应开放任何“在线支付/支付后自动审核”的承诺。

如需开放校园外卖、服务商品或兼职发布费，必须先完成：

1. 微信支付商户号、商户证书、平台证书、API v3 密钥和回调 HTTPS 地址配置在服务端密钥目录；不得进入仓库或小程序包。
2. 将生产环境切换为 `CHECKOUT_MODE=wechat`，并运行 `npm --prefix server run preflight:production -- --check-files`。
3. 用真实测试订单验证：支付成功、重复回调、取消、超时释放库存、退款申请、退款回调、人工异常处理。
4. 公示售价、退款/售后、配送范围、履约责任与投诉联系方式；每个校区先建立商家、骑手/取餐人员和当日库存。

## P1：建议在公开前完成

1. 配置 `NOTIFY_WEBHOOK_URL` 和密钥，接入合规的订阅消息/企业微信/短信通道，并对发件箱失败建立告警。当前通知只会安全留在 `notification_outbox`，不会送达工作人员。
2. 配置 DeepSeek 文本服务；如开放“课表图片一键导入”，还需独立的 OCR 服务和图像数据处理说明。未配置时当前页面会明确提示，而不会伪造识别结果。
3. 快递功能仅在获得驿站/快递公司书面接口授权后再做自动同步；多多快递当前仅能打开官方取件页，不能读取或回传包裹信息。
4. 生产数据库与上传目录已完成独立备份并验证归档，且已设每日定时备份；最新备份已成功恢复到临时数据库，检查出 54 张公共表与迁移表，演练库已清理。仍需将备份异地保留。
5. 2026-08-23 复核服务器根分区使用率为 89%，尚有约 4.4 GiB；仍需增加磁盘告警并定期把已核验备份转存异地，未经确认不得删除其他项目数据。
5. 对前端构建依赖进行安全升级评估。当前 `npm --prefix server audit --omit=dev` 为 0 漏洞；根目录依赖审计仍有 29 项上游 Taro/H5 工具链告警（6 critical、7 high、16 moderate），不能直接当作“已解决”，也不要执行 `npm audit fix --force`。应在 Taro 官方修复版本或经过完整 H5/小程序回归的兼容升级后处理。

## 发布顺序

1. 完成 P0 材料和生产变量核验，先对数据库做可恢复备份。
2. 用开发者工具真机预览完成核心回归，再把已通过版本提交微信审核。
3. 审核通过后，仅为唐山学院南院做小范围灰度；北院、华岩路、东院在运营人员和真实内容未配齐前继续保持小范围测试。
4. 灰度期间每日检查：接口错误率、待审帖子、举报、失败通知、订单/退款异常和用户反馈。
5. 连续稳定运营后再逐校区开通，支付、自动快递、OCR 等能力按各自的外部授权单独灰度。
