# 校园服务产品调研与实现准则

> 范围：唐山学院首发租户；面向中国在校大学生。调研日期：2026-07-29。

## 已观察到的证据

1. 校园墙既承担实用信息分发，也承担二手流通、生活便利和情绪交流。南京大学转引的中青校媒调研中，受访大学生认可其快速获取实用信息（73.18%）、促进二手流通（68.57%）和提升生活便利（52.75%）；同时，广告、兼职诈骗、谣言、刷屏、攻击和隐私泄露是显著风险。
   - 来源：<https://www.nju.edu.cn/info/1056/458831.htm>
2. 校园二手的核心不是“发布列表”，而是同校范围、可信身份、成色信息、线下当面验货和交易状态。高校二手交易研究反复指出信息不对称、渠道不成熟和缺少保障是主要障碍。
   - 来源：<https://www.zgkjcy.com/CN/10.3969/j.issn.1672-2272.2018.02.016>
   - 来源：<https://www.hanspub.org/journal/paperinformation?paperid=124302>
3. 校园生活服务在真实高校产品中常覆盖代取快递、洗护、团购、校园墙、失物、二手和兼职；但每一项的交付边界必须清晰，不能把需求收集包装成已履约的商品服务。
   - 来源：<https://cxcyxy.ldu.edu.cn/info/1118/2083.htm>
4. 校园社区需要“校内身份可信”与“匿名表达边界”同时成立。匿名社区的价值来自表达和互助，但身份核验、举报、内容治理和隐私保护是上线前置条件。
   - 来源：<https://chun-ge.github.io/documents/management-docs/vision.html>
   - 来源：<https://cjjc.ruc.edu.cn/CN/Y2018/V40/I5/160>

## 产品判断（基于上述证据的推断）

- 学生打开小程序的第一诉求是**立即办事**：查课、拿快递、找物、找二手、报名、找校内互助；首页和服务页应把状态、下一步和地点说清楚。
- 交易、兼职、跑腿和社区是高风险面。每个功能都要有：范围说明、状态闭环、风险提示、举报入口或上架前审核边界；不能只留下一个“发布”按钮。
- “独立小程序标准”不等于重复做一套大首页，而是每项服务都具备自己的：发现/筛选、创建或申请、我的记录、状态反馈、异常与安全说明。
- UI 使用明快、卡片化、低学习成本的蓝白底色，辅以场景色区分；信息密度优先于大面积装饰，底部操作固定且可见。

## 已识别缺口与开发顺序

| 优先级 | 服务 | 当前缺口 | 本轮目标 |
| --- | --- | --- | --- |
| P0 | 二手交易 | 收藏和发布已可用，但没有详情、预留/售出状态、我的发布和安全交易闭环 | 完成同校交易生命周期 |
| P0 | 跑腿代取 | 标签未筛选，发布/接单/完成缺少取消、我的任务和交接规则 | 完成任务大厅与任务状态闭环 |
| P0 | 快递动态 | 仅能手动新增、标记取件，待取/历史标签无效 | 完成待取、已取、取件码保护与站点筛选 |
| P1 | 兼职信息 | 缺少筛选、申请记录、截止/风险信息的统一呈现 | 完成岗位筛选与投递记录 |
| P1 | 校园活动 | 缺少分类、报名凭证、满额状态和我的活动 | 完成报名与入场信息闭环 |
| P1 | 课表、失物、搭子、校园商店 | 部分操作仍是静态标签或通用需求表单 | 分别补齐各自的发现、记录和安全流程 |

## 不做的事

- 不伪造微信登录、支付、实时物流或商家实时响应。
- 不公开手机号、宿舍精确房间、证件/取件码等敏感信息。
- 不绕过社区审核、举报、封禁和审计的上线前置要求。
