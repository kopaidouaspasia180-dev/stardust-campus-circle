## 已交付的业务闭环

- 唐山学院与唐山师范学院、六个校区的选择和服务端隔离。
- 午餐预约、按日期发布的每日菜单/套餐、库存锁定、10:30 截止、重复提交保护、订单状态、取消释放库存；运营端可查看当天可售/已预约数量、编辑当日价格和容量、暂停或恢复售卖，且不会把容量降到既有预约以下。
- 商家接单/拒单/出餐/自取完成；骑手抢单/取餐/送达。
- 微信登录服务端会话；学校管理员、档口员工和骑手最小权限。
- 顾客订单页的继续支付、取消、退款中/已退款提示。
- 微信支付 JSAPI、回调验签、退款队列与退款回调代码路径。
- 支付和退款回调除验签外，还校验本地订单的商户号、AppID、订单号与人民币分金额；生产环境必须明确选择 `CHECKOUT_MODE=wechat` 或 `offline`，选择在线支付但证书不完整会拒绝启动。
- 小程序内商家工作台、骑手工作台、午餐运营管理台；管理员可维护档口、菜品、骑手和授权。
- “DeepSeek 校园助手”已改为服务端校区知识库优先、DeepSeek 文本服务兜底；答案返回来源标签，管理员可维护校区 FAQ，不再在客户端伪造回答。
- OpenID、联系人、手机号、配送地址的服务端 AES-256-GCM 加密；注销、会话退出与交易记录留存边界。
- 社区、二手、兼职和活动接口按学校隔离；活动报名以行锁串行化容量校验；图片仅接受本服务验证过文件头的 JPEG/PNG/WebP 上传地址。
- 社区不再展示演示账号内容；校园圈帖子通过本地屏蔽词与微信内容安全检测后立即公开，最多支持 9 张图，并保留用户举报、管理员删除、处理记录与校区隔离。
- 数据库迁移锁、可追溯的前向迁移与校验和、Docker 镜像、健康/就绪探针、CI 验证、构建期 API/上传域名注入；生产环境预检会在部署前检查登录、加密、支付模式、HTTPS 回调和危险联调开关，且不输出密钥值。
- 提供生产 Compose 模板、API/数据库健康检查及带完整性校验的 PostgreSQL 备份脚本；恢复脚本需显式确认目标备份文件，避免误覆盖。
- GitHub Actions 会启动 PostgreSQL、执行迁移并运行上述集成回归；新改动不能只靠前端构建通过。

## 上线前仍必须完成的外部验收

以下不是代码可以替代的事项，因此当前版本**不能表述为已经在微信生产环境上线**：

1. 正式小程序 AppID、AppSecret、微信公众平台合法域名和隐私保护指引。
2. 正式 PostgreSQL、备份/恢复演练、密钥托管与生产环境变量。
3. 微信支付商户号、API v3 证书、平台证书、支付与退款回调公网 HTTPS 验签联调。
4. 微信订阅消息模板、用户订阅授权、通知网关与失败告警。
5. 每个实际营业校区的档口、每日菜单、库存、取餐点、配送范围、费用和骑手排班；运营人员需先创建菜品模板，再为每个营业日期发布菜单。
6. 主体资质、餐饮与配送责任、退款售后规则、隐私政策和数据留存期限的法务/运营审核。
7. 用正式 AppID 在微信开发者工具和真机完成登录、支付、通知、弱网和售后回归。
8. 如启用开放式校园 AI，配置 DeepSeek 官方文本接口的 `DEEPSEEK_API_BASE`、`DEEPSEEK_API_KEY`、`DEEPSEEK_MODEL`；如启用课表图片识别，还需配置独立的 DeepSeek-OCR 推理地址 `DEEPSEEK_OCR_API_URL`、`DEEPSEEK_OCR_API_KEY`、`DEEPSEEK_OCR_MODEL`。上线前确认内容安全、数据处理、图片留存和人工知识库审核策略。

## 推荐上线顺序

1. 在密钥平台配置 `server/.env.example` 中列出的生产变量，尤其是 `PII_ENCRYPTION_KEY`、`IDENTITY_HASH_SECRET`、微信登录和支付变量。
2. 使用 `npm --prefix server run migrate` 初始化生产数据库，再由学校运营管理员建立真实档口、菜品与履约账号。
3. 使用非敏感构建变量 `TARO_APP_API_ROOT`、`TARO_UPLOAD_ORIGIN` 构建小程序包，并在微信公众平台登记对应域名。
4. 先用体验版在一个校区灰度：登录 → 下单 → 支付 → 商家 → 骑手 → 通知 → 退款。
5. 通过实际运营日复盘后再逐校区开通；未开通校区保持“暂未开通”，不要展示演示菜单。
